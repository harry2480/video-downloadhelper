# Video Download Helper - サービスドキュメント

## サービス概要

Video Download Helper は、閲覧中の Web ページが読み込んでいる動画・音声ストリームを自動的に検出し、利用可能な品質を一覧表示して保存できる Chrome / Chromium 系ブラウザ向けの拡張機能です。

MP4 / WebM 等の直接ダウンロード可能なメディアに加え、HLS（`.m3u8`）・MPEG-DASH（`.mpd`）といった分割配信ストリームをブラウザ内だけで再構成します。外部サーバー・コンパニオンアプリ・ネイティブバイナリを一切必要とせず、検出から結合・保存までをユーザー端末内で完結させます。

対象は **ユーザー自身がアクセス権限を持ち、かつダウンロードが許可されているコンテンツ** に限定します。DRM（Widevine / FairPlay / PlayReady）等により技術的なアクセス制御が施されたコンテンツの解除・復号は実装しません。また YouTube 等、利用規約および Chrome Web Store ポリシー上ダウンロードが禁止されるサイトは、ブロックリストにより機能そのものを無効化します。

## コンセプト

### 1. 検出の自動化 —「何が保存できるか」を考えさせない

**目的**: ユーザーが URL や開発者ツールを調べることなく、保存可能なメディアへ到達できるようにする

**機能**:
- `chrome.webRequest` によるネットワークリクエスト監視（Content-Type / URL パターンからの形式判定）
- Content Script による `<video>` / `<audio>` / `<source>` 要素と MutationObserver での DOM 監視
- ネットワーク検出と DOM 検出の結果を統合し、URL 正規化により重複を排除（ネットワーク検出の情報を優先）
- ツールバーアイコンのバッジへタブ単位の検出件数を表示

### 2. 分割ストリームの透過的な再構成

**目的**: HLS / DASH のようにセグメント分割された配信を、ユーザーから見て「1つのファイル」として扱えるようにする

**特徴**:
- HLS Master Playlist を解析し、解像度・ビットレートごとの Variant を選択可能な形で提示
- DASH MPD の AdaptationSet / Representation を解析し、映像品質と音声トラックを個別に選択可能
- 映像・音声が分離しているストリームは ffmpeg.wasm で 1 ファイルへ Mux
- Manifest V3 の Service Worker では `URL.createObjectURL` が使えないため、セグメント結合・Blob 生成・ffmpeg 実行は Offscreen Document へ委譲する

**参考事例**: 既存のブラウザ拡張型ダウンローダー全般
- 多くはコンパニオンアプリのインストールを前提とする → 本拡張は初期版から拡張機能単体で完結させる
- 多くは対応サイトを増やすためにサイト固有ロジックを抱える → 本拡張は汎用的なプロトコル解析のみで対応する

### 3. ローカル完結・ゼロテレメトリ

**目的**: 「閲覧履歴を覗く拡張機能」という最大の懸念を、設計レベルで成立させない

**主要方針**:
- **外部送信の禁止**
  - 閲覧 URL・メディア URL・ページタイトルを外部サーバーへ送信しない
  - 初期実装では利用状況テレメトリを一切送信しない
- **認証情報の非保持**
  - Cookie / Authorization ヘッダーをログや storage へ保存しない
  - デバッグログでは URL クエリの認証トークンをマスキングする
- **状態の短命化**
  - 検出結果は原則としてタブのライフサイクル中のみ保持し、タブを閉じた時点で破棄する

### 4. 対応可否の明示 —「できない」を黙らない

**目的**: 検出したが保存できないケースで、ユーザーを無言のまま放置しない

**対象と機能**:
- **DRM 保護コンテンツ**
  - `ContentProtection` / Widevine 等の情報から DRM 候補と判定
  - 一覧上で「DRM で保護されているため対応していません」と明示し、ダウンロード操作を提供しない
- **再フェッチ不能なマニフェスト**
  - 認証付き・有効期限付き URL 等で拡張機能側から再取得できない場合は対応外として理由を表示
- **サイズ・形式の制約**
  - Blob 組み立て方式の上限（目安 2GB）超過が見込まれる場合は事前に警告
  - Phase 1 では fMP4 セグメントの HLS を対応外として明示

## 期待される効果

1. **保存手段の民主化** - 開発者ツールや外部ツールの知識がなくても、権利上問題のないメディアを保存できる
2. **プライバシー不安の解消** - ローカル完結・ゼロテレメトリにより、閲覧履歴の外部流出リスクを構造的に排除する
3. **保守可能な対応範囲** - サイト固有ハックを持たず HLS / DASH の標準仕様のみに依存することで、サイト側の変更による破損を最小化する
4. **段階的な拡張性** - Firefox / Edge への横展開、ライブ録画、字幕取得を見据えた共通コア層を初期段階から分離する

## 技術スタック（想定）

- 対象ブラウザ: Google Chrome / Chromium 系（Manifest V3）
- UI: React + Tailwind CSS（Popup）
- 言語: TypeScript
- ビルド: Vite + `@crxjs/vite-plugin`
- 実行基盤: Background Service Worker / Offscreen Document / Content Script
- メディア処理: 独自 HLS / DASH パーサー + ffmpeg.wasm（Offscreen Document 内で実行）
- 永続化: `chrome.storage.local` / `chrome.storage.session`
- テスト: Vitest（Unit / Integration）+ Playwright（E2E）

## スコープ外

- DRM 保護コンテンツの復号・回避
- YouTube 等ブロックリスト対象サイトへの対応、およびサイト固有の検出ロジック
- Native Messaging / 外部コンパニオンアプリを前提とした処理（将来の拡張として検討）
- サーバーサイドコンポーネント全般（本プロダクトはバックエンドを持たない）
