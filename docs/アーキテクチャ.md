# Video Download Helper アーキテクチャ設計規約

pnpm workspace + Vite（`@crxjs/vite-plugin`）+ Chrome Manifest V3 における拡張機能の設計規約。
`apps/extension/src/` 配下に適用する。

本拡張はサーバーサイドを持たない。したがって「DDD 4 層（presentation / application / domain / infrastructure）」ではなく、
**「実行コンテキスト層」と「コアロジック層」の 2 分割** を基本構造とする。

---

## 2 層構造

| 層 | ディレクトリ | 責務 |
|---|---|---|
| 実行コンテキスト層 | `background/` `offscreen/` `content/` `popup/` | Chrome 拡張の実行環境ごとの入口。`chrome.*` API・DOM・ffmpeg.wasm 等の副作用を担い、コアロジックへ注入する |
| コアロジック層 | `processor/` `media/` `shared/` | メディア検出・マニフェスト解析・URL 正規化・ファイル名生成等のビジネスルール。**副作用を持たない** |

コアロジック層は Node.js 上（Vitest）でそのまま実行できることを設計上の必須条件とする。ここが崩れるとテスト戦略全体が成立しない。

## 依存方向（厳守）

```text
background ─┐
offscreen  ─┤
content    ─┼──→ processor ──→ media ──→ shared
popup      ─┘
```

- **shared は最内層。** 他ディレクトリへの依存禁止
- **media は shared にのみ依存。** processor / 実行コンテキストへの依存禁止
- **processor は media, shared に依存可。** 実行コンテキストへの依存禁止
- **実行コンテキスト層はコアロジック層を参照可。** 逆方向は禁止
- **実行コンテキスト同士の import は全面禁止。** background / offscreen / content / popup は別プロセス・別バンドルであり、直接 import は成立しない。相互作用は必ず `shared/messages.ts` で定義したメッセージ経由で行う
- コアロジック層（`processor/` `media/` `shared/`）での **`chrome.*` / `document` / `window` / `Blob` の参照禁止**

**唯一の例外: `shared/storage/`。** Repository は `chrome.storage` を直接呼ぶ（`リポジトリ層設計規約.md` 参照）。全コンテキストから使うため `shared/` に置く必要がある一方、`chrome.storage` の制約（構造化クローン・容量上限・`session` の生存期間）はモックで再現できず Unit テストの対象にならないため、純粋性を要求しない。

この例外がコアロジック層へ波及しないよう、**`media/` `processor/` から `shared/storage/` への依存を禁止する**。両者が純粋であり続けることが Unit テストの前提条件であり、ここが崩れるとテスト戦略全体が破綻する。

これらは dependency-cruiser で機械的に検証する（`品質チェック・テスト規約.md` 参照）。

## 実行コンテキスト層: 4 つの入口

Chrome 拡張と本アプリケーションの唯一の接続点。**それぞれのエントリファイルが Composition Root を兼ねる。**

**エントリのファイル名は全コンテキストで一意にする。** すべて `index.ts` にすると、CRXJS が
`service-worker-loader.js` を別のコンテキストのバンドルへ紐づけてしまい、Service Worker は
起動するが中身が別物という形で静かに壊れる。`service-worker.ts` / `content-script.ts` /
`offscreen.ts` / `main.tsx` のように役割を名前に含めること。

| コンテキスト | 責務 | 保持してよい状態 |
|---|---|---|
| background (Service Worker) | webRequest 監視、検出結果の集約、タブ状態管理、ダウンロードのオーケストレーション | 検出結果・ダウンロードタスク（storage へ復元可能な形で） |
| offscreen (Offscreen Document) | セグメント取得、Blob 生成、`URL.createObjectURL`、ffmpeg.wasm 実行 | 実行中ダウンロードのバイト列（一時的） |
| content (Content Script) | `<video>` / `<audio>` 要素と DOM 変化の監視、ページメタデータ抽出 | なし（検出のたびに background へ送信） |
| popup (React) | 検出結果の表示、品質選択、ダウンロード指示 | なし（表示用のローカル state のみ） |

- **popup は状態を所有しない。** ポップアップはいつ閉じられてもよい前提とし、検出状態・ダウンロード進捗は background / offscreen 側が所有する。popup は表示時に購読して描画するだけ
- **Service Worker は常駐しない前提で書く。** 長時間処理（セグメント取得・結合）は offscreen へ委譲し、SW の停止で中断されない構成とする。background が持つ状態は SW 再起動後に storage から復元できる形で保持する
- **Composition Root（各エントリ）以外で副作用実装を new しない。** Port 実装（adapter）の生成はエントリに閉じ込め、以降は interface として引き回す

## Port / Adapter パターン

コアロジック層は副作用を **Port（interface）** として宣言し、実行コンテキスト層がその実装（**Adapter**）を注入する。

| Port | interface 配置 | 実装配置 | 用途 |
|---|---|---|---|
| `MediaFetcherPort` | `shared/ports/media-fetcher.port.ts` | `offscreen/`, `background/` | マニフェスト再フェッチ・セグメント取得 |
| `DownloadPort` | `shared/ports/download.port.ts` | `background/` | `chrome.downloads` 経由の保存 |
| `BlobAssemblerPort` | `shared/ports/blob-assembler.port.ts` | `offscreen/` | セグメント結合・Blob 生成・オブジェクト URL 発行 |
| `MuxerPort` | `shared/ports/muxer.port.ts` | `offscreen/` | ffmpeg.wasm による Mux / リマックス |
| `MessagingPort` | `shared/ports/messaging.port.ts` | 全コンテキスト | `chrome.runtime` メッセージ送受信 |
| Repository | `shared/storage/*.repository.ts` | 同左（`chrome.storage` 実装を内包） | 検出結果・設定・ダウンロード状態の永続化（`リポジトリ層設計規約.md` 参照） |

- Port は「拡張機能側が必要とする最小の操作」で定義する。`chrome.*` の型をそのまま露出させない
- 各 Port には **テスト用の Fake 実装** を用意し、Unit テストではそれを注入する
- ffmpeg.wasm のようにロードコストが高い実装は、Adapter 内で遅延初期化する

## メディアモデル設計

**Rich Domain Model を徹底する。生成・検証・変換はモデル自身のメソッドで行う。**

- `DetectedMedia` / `MediaVariant` / `DownloadTask` の生成はファクトリ関数（`createDetectedMedia` 等）を経由し、不正な状態のオブジェクトを作れないようにする
- URL 正規化・重複判定キーの算出・DRM 候補判定・ブロックリスト判定は、呼び出し側に書かずモデル / `media/` 配下の関数に閉じる
- 解析失敗（マニフェスト不正・再フェッチ失敗・非対応形式）は例外ではなく `Result<T, E>` 型で返す。実行コンテキスト層でユーザー向けメッセージへ変換する
- 複数モデルの協調が必要な処理のみ `media/detector.ts` 等のサービス的モジュールへ置く

## 実装規約

- **ファイル命名: kebab-case + 役割サフィックス**（`.parser.ts` / `.port.ts` / `.adapter.ts` / `.repository.ts` / `.model.ts`）。React コンポーネントのみ PascalCase
- **`index.ts` によるバレルエクスポート禁止。** `index.ts` というファイル名自体を使わない
- **`any` 禁止。** 外部由来（マニフェスト文字列・メッセージ・ページ由来データ）は必ず境界でパースして型を確定させる
- **コアロジックは関数エクスポートを基本とする。** 状態と依存を持つオーケストレーター（`MediaRegistry`, `DownloadManager` 等）のみクラス + コンストラクタ DI とする
- **メッセージは判別可能ユニオンで定義する。** `shared/messages.ts` に集約し、送信・受信の双方でネロー化する
- **拡張機能内部メッセージは送信元を検証する。** `sender.id !== chrome.runtime.id` のメッセージは破棄する
- **ページ由来の文字列を `innerHTML` へ渡さない。** React のテキストノードとして描画する

## データフロー

```text
[Web ページ]
    │  webRequest / DOM
    ▼
content ──message──┐
                   ▼
              background (MediaRegistry)
                   │  media/ で形式判定・マニフェスト解析
                   │  ※ マニフェスト本文は再フェッチで取得
                   ▼
              検出結果 + バッジ更新 ──subscribe──► popup
                                                   │ ダウンロード指示
                                                   ▼
                                            background (DownloadManager)
                                                   │
                          ┌────────────────────────┴───────────────────┐
                          ▼ direct                                     ▼ HLS / DASH
                   chrome.downloads                              offscreen
                                                                  ├─ SegmentFetcher
                                                                  ├─ BlobAssembler
                                                                  └─ FFmpegRunner
                                                                       │ objectURL
                                                                       ▼
                                                                chrome.downloads
```

進捗は offscreen → background → popup の一方向で伝搬させる。popup が閉じていても background が状態を保持し続ける。
