# Video Download Helper拡張機能 要件定義書

## 1. 概要

Chrome / Chromium系ブラウザ向けに動画ダウンロード支援拡張機能を実装し、ユーザーが閲覧中のWebページから動画・音声ストリームを検出し、保存可能なメディアを一覧表示してダウンロードできるようにする。

主な対象は、通常の動画ファイル（MP4 / WebM等）、HLS（m3u8）、DASH（MPD）、音声ストリーム等とする。

本機能は、ユーザー自身がアクセス権限を持ち、かつダウンロードが許可されているコンテンツの保存支援を目的とする。DRM等により技術的なアクセス制御が施されたコンテンツの解除・復号は対象外とする。

## 2. 機能要件

### 2.1 基本機能

* **メディア検出**: 現在表示中のページで読み込まれた動画・音声リソースを自動的に検出
* **通常動画対応**: MP4、WebM、MOV、M4V等の直接URL形式のメディアを検出
* **HLS対応**: `.m3u8` プレイリストを検出し、HLSストリームとして認識
* **DASH対応**: `.mpd` マニフェストを検出し、MPEG-DASHストリームとして認識
* **音声対応**: M4A、AAC、MP3、Opus、WebM Audio等の音声リソースを検出
* **複数品質検出**: HLS / DASH等で複数解像度・ビットレートが存在する場合、利用可能な品質を一覧表示
* **メディア情報表示**: 検出したメディアについて、URL、形式、解像度、ビットレート、推定ファイルサイズ等を可能な範囲で表示
* **ダウンロード**: 検出したメディアをブラウザから保存可能にする
* **ストリーム結合**: HLS / DASH等の分割されたメディアについて、必要に応じてセグメントを取得・結合して単一ファイルとして保存
* **映像・音声結合**: DASH等で映像と音声が分離されている場合、両方を取得して1ファイルへ結合
* **ファイル名生成**: ページタイトル、動画タイトル、解像度等を利用して保存ファイル名を自動生成
* **重複排除**: 同一URL・同一ストリームを複数回検出した場合は重複表示しない
  * URLはクエリパラメータを正規化したうえで比較する
  * `<video>` 要素検出とネットワーク検出の両方で同一メディアを検出した場合は1件に統合する（ネットワーク検出の情報を優先）
  * ライブHLS等でMedia Playlistが繰り返しリロードされる場合も1件として扱う
* **タブ単位管理**: 検出結果はブラウザタブ単位で管理
* **対象外サイト**: YouTube等、利用規約およびChrome Web Storeポリシー上ダウンロードが禁止されるサイトではブロックリストにより機能を無効化する
* **リアルタイム検出**: SPAや遅延ロードに対応し、ページ表示後に発生したネットワークリクエストも継続監視
* **DRM判定**: DRM保護されている可能性のあるメディアを検出した場合、ダウンロード対象外として明示
* **対応外通知**: 保存できない形式や保護されたメディアの場合、理由をユーザーに表示

### 2.2 メディア検出要件

* **Network Request監視**: ページ内で発生するメディア関連HTTPリクエストを監視
* **Content-Type判定**: HTTPレスポンスヘッダーの `Content-Type` を利用してメディア形式を識別
* **URL拡張子判定**: `.mp4`、`.webm`、`.m3u8`、`.mpd` 等のURLパターンから形式を識別
* **HTML要素検出**: `<video>`、`<audio>`、`<source>` 要素から直接参照されているURLを検出
* **MediaSource対応**: Media Source Extensionsを利用するサイトについても、取得可能な元ストリームURLをネットワークレベルで検出
* **Blob URL判定**: `blob:` URL自体を保存対象とせず、元となるネットワークリソースを特定
* **XHR / Fetch監視**: JavaScript経由で読み込まれるHLS / DASHマニフェスト等を検出
* **再フェッチ方式**: Chrome拡張はネットワークレスポンスのボディを読み取れない（`webRequest.filterResponseData` はFirefox専用）ため、マニフェスト内容の判定・解析は検出したURLを拡張機能側で再フェッチして行う。認証・有効期限付きURL等で再フェッチに失敗する場合は対応外として扱う
* **動的ページ対応**: ページ遷移を伴わないSPAでも検出状態を適切に更新
* **検出結果リセット規則**: メインフレームのページ遷移時は当該タブの検出結果をクリアする。History API等によるSPA内遷移では検出結果を維持しつつ継続監視する。タブを閉じた場合は破棄する

### 2.3 HLS要件

* **Master Playlist解析**: HLS Master Playlistを解析
* **Variant Stream取得**: 各解像度・ビットレートのVariant Streamを取得
* **Media Playlist解析**: セグメントURLを解析
* **セグメント形式判定**: TSセグメントとfMP4セグメント（`#EXT-X-MAP` あり）を判別する
* **fMP4対応**: `#EXT-X-MAP` で指定されるInitialization Segmentを取得し、メディアセグメントと正しく結合する（Phase 2）
* **byte-rangeセグメント対応**: `#EXT-X-BYTERANGE` によるバイトレンジ指定セグメントを取得可能とする（Phase 2）
* **相対URL解決**: マニフェスト内の相対URLを正規URLへ変換
* **AES-128対応**: ユーザーが正当にアクセス可能な通常のHLS AES-128暗号化ストリームについては、マニフェストで公開されるキーを利用した標準的な再構成を検討可能
* **DRM除外**: Widevine、FairPlay、PlayReady等のDRM保護コンテンツは処理対象外
* **ライブストリーム判定**: VODとLIVEを判別
* **LIVE保存**: 将来的にライブストリームの一定時間録画に対応可能な設計とする

### 2.4 DASH要件

* **MPD解析**: MPEG-DASH MPDマニフェストを解析
* **Representation取得**: 映像・音声のRepresentationを一覧化
* **AdaptationSet解析**: Video / Audio / Subtitle等を識別
* **映像・音声選択**: ユーザーが希望する映像品質と音声を選択可能
* **SegmentTemplate対応**: SegmentTemplate形式のURLを展開
* **SegmentList対応**: SegmentList形式を解析
* **BaseURL対応**: MPD内のBaseURLを適切に解決
* **DRM判定**: ContentProtection要素等からDRMの有無を可能な範囲で判定
* **DRM除外**: Widevine等のDRM保護されたRepresentationはダウンロード対象外

### 2.5 UI/UX要件

* **ツールバーアイコン**: Chromeツールバーの拡張機能アイコンから操作
* **検出件数バッジ**: 現在のタブで検出したメディア件数をアイコンバッジに表示
* **ポップアップUI**: アイコンクリック時に検出メディア一覧を表示
* **メディア一覧**: 動画ごとにタイトル、形式、解像度、推定容量等を表示
* **品質選択**: HLS / DASHの場合は希望品質を選択
* **ワンクリック保存**: 直接保存可能なファイルはボタン1つでダウンロード
* **詳細表示**: URL、Content-Type、検出方式等の詳細情報を展開可能
* **検出状態表示**: 「動画を検出中」「動画が見つかりません」等の状態を表示
* **更新ボタン**: 手動で現在タブのメディア情報を再スキャン可能
* **レスポンシブデザイン**: Chrome拡張ポップアップ内で見やすいレイアウト
* **アクセシビリティ**: キーボード操作、aria-label、十分なコントラスト等を考慮
* **ダークモード**: OSまたはブラウザ設定に応じてテーマ切替

### 2.6 ダウンロード管理要件

* **Chrome Downloads API利用**: 直接ダウンロード可能なメディアはChrome Downloads APIを使用
* **進捗表示**: ダウンロード中の進捗率を表示
* **キャンセル**: ダウンロード処理を途中で停止可能
* **失敗時再試行**: 通信エラー等で失敗した場合に再実行可能
* **並列取得制御**: セグメント取得時の同時接続数を制御
* **保存方式**: Manifest V3のService Workerでは `URL.createObjectURL` が使用できないため、セグメントの結合・Blob生成・オブジェクトURL発行は **Offscreen Document** 内で行い、`chrome.downloads` へ渡す
* **サイズ上限**: 初期版はBlob組み立て方式のため、1ファイルあたりの上限サイズ（目安: 2GB）を設け、超過が見込まれる場合はユーザーへ警告する。File System Access APIによる逐次書き込みは将来の拡張とする
* **ファイルサイズ推定**: Content-Lengthまたはビットレート等から推定容量を表示
* **保存先**: Chrome標準のダウンロード設定に従う

### 2.7 非機能要件

* **永続化**: 検出結果は原則タブのライフサイクル中のみ保持（リセット規則は2.2参照）
* **Service Worker非常駐対策**: ダウンロード等の長時間処理はOffscreen Document側で実行し、Service Workerの停止によって処理が中断されない構成とする。検出状態・ダウンロード状態はSW停止後に復元可能な形で保持する
* **Popup揮発性対応**: ポップアップはいつ閉じられても良い前提とし、ダウンロード進捗等の状態はService Worker / Offscreen側で管理する。ポップアップは表示時に最新状態を購読するのみとする
* **設定保存**: ユーザー設定は `chrome.storage.local` または `chrome.storage.sync` に保存
* **パフォーマンス**: 通常のブラウジングへ極力影響を与えない
* **低CPU使用率**: 不要なDOM監視やポーリングを避ける
* **低メモリ使用量**: 大容量動画データをService Worker内に長時間保持しない
* **エラーハンドリング**: ネットワークエラー、マニフェスト解析失敗、権限不足等を適切に通知
* **セキュリティ**: ページ由来の文字列やURLをUIへ表示する際にサニタイズ
* **プライバシー**: 検出した閲覧URLや動画URLを外部サーバーへ送信しない
* **ローカル処理優先**: メディア検出・解析は原則としてユーザー端末内で完結
* **テレメトリ**: 初期実装では利用状況データの外部送信を行わない

## 3. 技術仕様

### 3.1 使用技術スタック

* **対象ブラウザ**: Google Chrome / Chromium系ブラウザ
* **Extension仕様**: Manifest V3
* **言語**: TypeScript
* **UIフレームワーク**: React
* **ビルドツール**: Vite または WXT
* **スタイリング**: Tailwind CSS
* **状態管理**: React State + Chrome Storage
* **Service Worker**: Manifest V3 Background Service Worker
* **Offscreen Document**: `chrome.offscreen` — セグメント結合・Blob生成・`URL.createObjectURL`・ffmpeg.wasm実行の受け皿
* **Content Script**: ページDOM・video/audio要素の監視
* **Network監視**: `chrome.webRequest`（Manifest V3では観測のみ。リクエストURL・ヘッダーを取得し、ボディは再フェッチで取得）
* **ダウンロード**: `chrome.downloads`
* **タブ管理**: `chrome.tabs`
* **ストレージ**: `chrome.storage`
* **メッセージング**: `chrome.runtime.sendMessage` / `chrome.runtime.connect`
* **HLS解析**: 独自パーサーまたはOSSライブラリ
* **DASH解析**: XML Parser + 独自解析またはOSSライブラリ
* **メディア結合**: WebAssembly版FFmpeg等の利用を検討（実行はOffscreen Document内）
* **FFmpeg候補**: ffmpeg.wasm
* **i18n**: 初期版はUI文言を日本語固定とする。`chrome.i18n` による多言語化は将来の拡張とする
* **テスト**: Vitest
* **E2Eテスト**: Playwright

### 3.3 データフロー

1. ユーザーがWebページへアクセス
2. Background Service WorkerおよびContent Scriptが現在タブを監視
3. `<video>`、`<audio>`、ネットワークリクエスト等からメディア候補を検出
4. 検出したURLをMediaRegistryへ登録
5. URL、Content-Type、レスポンス情報等からメディア形式を判定
6. HLSの場合はm3u8を解析
7. DASHの場合はMPDを解析
8. 利用可能な解像度、ビットレート、音声等を抽出
9. ツールバーアイコンのバッジへ検出件数を表示
10. ユーザーが拡張機能のポップアップを開く
11. 現在タブのメディア一覧を表示
12. ユーザーが対象メディア・品質を選択
13. 直接URLの場合はChrome Downloads APIで保存
14. HLS / DASHの場合はOffscreen Documentがセグメントを取得
15. 必要に応じてOffscreen Document内で映像・音声を結合（ffmpeg.wasm）
16. Offscreen DocumentでBlob化・オブジェクトURL発行し、Chrome Downloads APIで保存
17. 完了状態をUIへ通知

## 6. メディア判定ロジック

### 6.1 Direct Media

以下に一致した場合、直接ダウンロード可能なメディア候補として登録する。

```text
video/mp4
video/webm
video/quicktime
audio/mpeg
audio/mp4
audio/aac
audio/ogg
```

またはURL末尾・パスに以下が含まれる場合：

```text
.mp4
.webm
.mov
.m4v
.mp3
.m4a
.aac
.opus
```

### 6.2 HLS

以下の条件に一致する場合、HLSとして扱う。

```text
Content-Type:
application/vnd.apple.mpegurl
application/x-mpegURL
```

または：

```text
*.m3u8
```

マニフェストに以下が含まれる場合、Master Playlistとして解析する。

```text
#EXT-X-STREAM-INF
```

### 6.3 DASH

以下の場合、MPEG-DASHとして扱う。

```text
Content-Type:
application/dash+xml
```

または：

```text
*.mpd
```

### 6.4 DRM

以下のような情報が存在する場合、DRM保護コンテンツ候補として扱う。

```text
Widevine
com.widevine.alpha

PlayReady

FairPlay

CENC

ContentProtection
```

DRMと判定されたコンテンツについては復号・回避処理を実装しない。

## 7. Manifest V3権限

本拡張機能の中核機能（任意のページでのネットワーク監視・Content Script注入）には、`webRequest` 権限と広範なホスト権限が**必須**である。「最小権限」ではなく「機能に必要な権限を明示的に要求し、用途を説明する」方針を取る。

```json
{
  "permissions": [
    "downloads",
    "storage",
    "webRequest",
    "offscreen"
  ],
  "host_permissions": [
    "<all_urls>"
  ]
}
```

補足:

* `webRequest` はManifest V3では観測専用であり、通信のブロック・改変は行わない
* `<all_urls>` はメディア検出（webRequest監視・Content Script注入・マニフェスト再フェッチ）に必要。Chrome Web Storeの審査向けに用途説明を用意する
* `tabs` 権限は要求しない。ホスト権限があればタブのURL・タイトルは取得可能であり、「閲覧履歴の読み取り」警告を避ける
* `declarativeNetRequest` は通信の変更・ブロック用であり、検出用途には使えないため採用しない
* 代替案として optional host permissions（サイトごとにユーザーが許可）も検討したが、検出漏れによるUX低下が大きいため初期版では採用しない

## 8. 制約事項

* DRM保護されたコンテンツの復号・回避は実装しない
* Widevine、FairPlay、PlayReady等のDRM解除は対象外
* ダウンロード可否は対象サイトの利用規約、著作権、ユーザーの権限等に依存する
* Chrome Manifest V3の制約上、従来の拡張機能と同じネットワーク監視方式が利用できない場合がある
* Service Workerは常駐を保証されないため、長時間処理をService Workerのみに依存しない
* 数GB規模の動画をJavaScriptメモリ上へ全展開しない
* クロスオリジン制約や認証Cookie等により、拡張機能から再取得できないメディアが存在する
* `blob:` URLのみ取得できても、必ずしも元ストリームを復元できるとは限らない
* HLS / DASHの仕様差異やサイト独自実装により、すべてのサイトへの対応は保証しない
* YouTube等、Chrome Web Storeポリシー上ダウンロードが禁止されるサイトはブロックリストで機能を無効化する（2.1参照）。特定サイト専用の検出ロジックも実装しない
* 初期版では外部コンパニオンアプリを必要としない構成を優先する
* 初期版のBlob組み立て方式では1ファイルあたりのサイズ上限（目安: 2GB）がある（2.6参照）

## 12. セキュリティ・プライバシー要件

* 閲覧履歴を外部サーバーへ送信しない
* メディアURLを外部サービスへ送信しない
* Cookie、Authorization Header等をログへ保存しない
* デバッグログでは認証情報をマスキング
* URLクエリに認証トークンが含まれる可能性を考慮
* Content Scriptから受け取るデータを信用せず検証する
* 任意URLへのリクエストを許可する機能を外部ページから呼び出せないようにする
* 拡張機能内部のメッセージについて送信元を検証する
* HTML文字列をそのまま `innerHTML` へ挿入しない
* Content Security Policyに準拠する
* リモートコードを実行しない
* Chrome Web Storeポリシーに準拠する
