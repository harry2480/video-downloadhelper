## 1. 未対応のレビュー指摘

PR #24 のレビューで挙がったもののうち、残っている 3 件。
いずれも LOW で、ユーザーが行き詰まる種類の問題ではない。

（1-1 取得失敗の永続化 / 1-2 `forgetTab` との競合 / 1-3 SW 再起動後の再解析は PR #31 で対応済み）

### 1-4. レスポンスボディを破棄していない（LOW）

`background/media-fetcher.adapter.ts:31`

`!response.ok` の早期 return でボディを消費も cancel もしていない。検出のたびに
再フェッチする性質上、ストリームと接続が GC まで残る。

なお `offscreen/segment-fetcher.ts` は同じ経路で `await response.body?.cancel()` を
呼んでいる（PR #33）。**揃っていないのはこの 1 か所だけ。**

対応案: HTTP エラー経路で `await response.body?.cancel()` を呼ぶ。

### 1-5. 品質選択が variants と突き合わされていない（LOW）

`popup/components/MediaItem.tsx:36`

`selectedVariantId` は `media.variants` と照合されない。variant の id は
`analysis.ts` の並べ替え後に付ける位置ベース（`v0`, `v1`, …）。`MediaList` は
`media.id` をキーにするため variants だけが変わっても再マウントされない。

再解析で品質の本数が変わると、保持していた id が別の品質を指すか、
どれにも一致せず**ラジオがどれも選択されていない状態**になる。

保存の実装後は影響が広がっている。`DownloadControl` は `variantId` から variant を
解決して保存可否を判定するため（PR #32 のレビュー対応）、id がずれると
「保存ボタンが出ない」または「意図しない品質で保存する」ことになる。

対応案: variant の id 一覧を依存にしたリセットを入れる。

### 1-6. 再取得抑止のテストが実効性を欠く（LOW）

`test/integration/manifest-resolution.test.ts:69`

「同じマニフェストを繰り返し取得しない」の判定が `toBeLessThanOrEqual(2)` という
上限のみ。Playwright が拡張機能側の `fetch` を context のリクエストとして
surface しない場合、**観測できていなくても通る**。加えて `context.on('request', …)` を
登録したまま解除していない。

対応案: 拡張機能の再フェッチが実際に観測できることを確かめたうえで、正確な件数で判定する。

## 2. 保留中の判断

### 2-1. 再フェッチとセグメント取得の `credentials: 'include'`

`background/media-fetcher.adapter.ts` / `offscreen/segment-fetcher.ts`

**指摘**: ページが選んだ URL に対し、`<all_urls>` を持つ拡張機能から
ユーザー操作なしで credentialed な GET を発行している。CORS プリフライトも
SameSite も効かないため、ページ単体ではできない要求を代行させられる。

**保留の理由**: 提案された緩和策には機能上の代償がある。

- same-origin 限定 → CDN 配信のマニフェスト・セグメントが取得できなくなる。
  実際の配信構成として一般的で、影響が大きい
- `redirect: 'error'` → CDN のリダイレクトで失敗する

**PR #33 で入れた緩和**（この判断とは独立して実施済み）:

- セグメント URL を `http(s)` に限定
- プライベートネットワーク宛は、検出元のメディア URL 自体がプライベートな場合のみ許可
  （ページが差し替えられない値＝webRequest で観測した URL を材料にする）
- リダイレクトの**着地点**にも同じ宛先ポリシーを当て、外れていれば本文を読まずに捨てる

**判断が必要な論点（残り）**: リダイレクト先への**リクエスト自体は 1 回飛ぶ**。
これはページが `fetch(..., { mode: 'no-cors' })` を投げるのと同等で、拡張機能が
上乗せしているのは「応答がディスクへ保存される」経路のみ（そこは塞いだ）。
事前に完全に遮断するかどうかは、リダイレクト追随の可否そのものの判断になる。
