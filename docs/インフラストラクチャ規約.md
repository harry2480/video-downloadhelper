# Video Download Helper インフラ規約

pnpm workspace + Vite（`@crxjs/vite-plugin`）+ GitHub Actions + Chrome Web Store によるビルド・配布環境の構成と規約。

本プロダクトはサーバーサイドを持たない。したがってホスティング・データベース・環境変数管理は存在せず、
インフラの関心事は **「再現可能なビルド」と「ストアへの安全な配布」** に限られる。

---

## Monorepo 構成

pnpm workspace で管理。`apps/` 配下に各アプリケーションを配置する。

```text
video-downloadhelper/
├── apps/
│   └── extension/         # Chrome 拡張機能（Vite + React + TypeScript）
│       ├── src/
│       ├── public/        # アイコン等の静的アセット
│       ├── dist/          # ビルド成果物（gitignore）
│       ├── vite.config.ts
│       └── package.json
├── docs/
├── pnpm-workspace.yaml    # packages: apps/*
├── biome.json             # 共有 lint/format 設定
├── knip.json              # 未使用コード検出設定
└── package.json           # workspace scripts
```

Next.js スターターの残骸（`apps/webapp/`、Prisma / Supabase / Vercel 関連の設定）は撤去済み。
本リポジトリの workspace メンバーは `apps/extension` のみとする。

## ビルド

### Vite + CRXJS

- Manifest は `src/manifest.json` を単一の情報源とし、`@crxjs/vite-plugin` がエントリ解決とビルド後の書き換えを行う
- 出力は `apps/extension/dist/`。このディレクトリをそのまま `chrome://extensions` の「パッケージ化されていない拡張機能を読み込む」で使える
- Offscreen Document は manifest に記述せず `chrome.offscreen.createDocument()` で生成するが、**HTML エントリを `vite.config.ts` の `build.rollupOptions.input` へ明示的に追加する**（CRXJS は manifest 経由のエントリしか自動検出しないため、指定を忘れると実行時に 404 になる）

### コマンド

| コマンド | 内容 |
|---|---|
| `pnpm dev` | Vite dev server + HMR。`dist/` を `chrome://extensions` へ読み込んで開発する |
| `pnpm build` | 本番ビルド。`apps/extension/dist/` を生成 |
| `pnpm package` | `dist/` を `video-downloadhelper-<version>.zip` へ固める（ストア提出用） |
| `pnpm verify` | 品質チェック一式（`品質チェック・テスト規約.md` 参照） |

### ビルド上の制約

- **リモートコードを実行しない。** 外部 CDN からのスクリプト・フォント・WASM の読み込みを禁止する（Chrome Web Store ポリシー / 要件定義 12 章）
- **ffmpeg.wasm は拡張機能内に同梱する。** `@ffmpeg/core` の `.wasm` / `.js` を `public/` へ配置し、Offscreen Document から相対パスでロードする
- **`web_accessible_resources` は最小限にする。** ページ側から到達可能なリソースを増やすと攻撃面が広がる
- **シークレットを同梱しない。** 拡張機能のバンドルはユーザーが完全に閲覧できる。API キー等を埋め込まない

## CI

GitHub Actions で以下を実行する。

| ワークフロー | トリガー | 内容 |
|---|---|---|
| `verify.yml` | PR 作成 / 更新、main への push | `pnpm verify`（lint → typecheck → unit test → depcruise → build） |
| `ci.yml` | PR 作成 / 更新 | Integration テスト（Chrome ヘッドレス）+ E2E テスト（Playwright） |
| `coverage.yml` | PR 作成 / 更新 | カバレッジ計測と Codecov への送信 |

- Node.js Version: 22.x
- Package Manager: pnpm 10.x（`packageManager` フィールドに従う）
- CI で拡張機能を起動する必要があるジョブでは、Playwright の Chromium を `launchPersistentContext` + `--load-extension` で使う（拡張機能は headless: true では動作しないため `--headless=new` を指定する）

ビルド成果物（zip）は PR ごとに artifact としてアップロードし、レビュアーが手元の Chrome へロードして確認できるようにする。

## リリース / 配布

| 環境 | トリガー | 配布先 | 備考 |
|---|---|---|---|
| ローカル検証 | 手動 | `chrome://extensions`（パッケージ化されていない拡張機能） | 開発時の既定 |
| PR 検証 | PR 作成 / 更新 | GitHub Actions artifact（zip） | レビュアーが手動ロード |
| Beta | `v*.*.*-beta.*` タグ | Chrome Web Store（限定公開 / テスターのみ） | 審査あり |
| Production | `v*.*.*` タグ | Chrome Web Store（公開） | 審査あり |

### バージョニング

- `src/manifest.json` の `version` を単一の情報源とし、Git タグと一致させる
- Chrome の `version` は数値 4 要素までしか許容しないため、プレリリース識別子は `version_name` に記述する

### Chrome Web Store 審査への備え

`<all_urls>` と `webRequest` という強い権限を要求するため、ストア掲載情報に以下を必ず用意する（要件定義 7 章）。

- **権限ごとの用途説明**
  - `webRequest`: ページが読み込むメディアリソースの URL と Content-Type を観測するため。通信のブロック・改変は行わない
  - `<all_urls>`: 任意のサイトでメディアを検出するため（Content Script 注入 / マニフェスト再フェッチ）
  - `downloads`: 検出したメディアを保存するため
  - `offscreen`: Service Worker で扱えない Blob 生成・オブジェクト URL 発行のため
  - `storage`: 検出結果とユーザー設定の保持のため
- **プライバシーポリシー**: 閲覧データ・メディア URL を外部送信しないこと、テレメトリを持たないことを明記する
- **単一目的の説明**: 「ユーザーがアクセス権を持つメディアの保存支援」であること、DRM 回避を行わないこと
- **ブロックリスト**: YouTube 等ポリシー上ダウンロードが禁止されるサイトで機能を無効化していることを明示する

## ローカル開発

```sh
pnpm install
pnpm dev
# chrome://extensions を開く
#   → デベロッパーモードを ON
#   → 「パッケージ化されていない拡張機能を読み込む」で apps/extension/dist/ を選択
```

- Service Worker のログは `chrome://extensions` の「Service Worker」リンクから開く DevTools で確認する
- Offscreen Document のログは `chrome://extensions` からは辿れないため、`chrome://inspect/#other` から開く
- Service Worker が停止した状態を再現するには、DevTools を閉じて 30 秒放置するか、`chrome://serviceworker-internals` から停止させる。**開発中は DevTools を開きっぱなしにすると SW が停止しなくなり、非常駐前提のバグを見逃す**
