# Video Download Helper 品質チェック規約

`vitest` + `TypeScript` + `dependency-cruiser` + `Biome` によるコード品質チェック規約。

---

## Quality Check 一覧

| チェック | ツール | 対象 | コマンド |
|---|---|---|---|
| Unit テスト | Vitest | `shared/`, `media/`, `processor/`（副作用なしのコアロジック層） | `pnpm test:unit` |
| Integration テスト | Vitest + Chrome | `background/`, `offscreen/`, `content/`, `shared/storage/`（`chrome.*` 依存） | `pnpm test:integration` |
| E2E テスト | Playwright | 拡張機能全体のユーザーフロー | `pnpm test:e2e` |
| 型チェック | `tsc --noEmit` | 全ソース | `pnpm typecheck` |
| 依存方向チェック | dependency-cruiser | 全ソース | `pnpm depcruise` |
| リンター / フォーマッター | Biome | 全ソース | `pnpm lint` |
| 未使用コード検出 | knip | 全ソース | `pnpm knip` |
| ビルド検証 | Vite + CRXJS | manifest / エントリ解決 | `pnpm build` |

### verify コマンド 実行フロー

`pnpm verify` は以下の順序で実行する。

1. lint（Biome）
2. typecheck（`tsc --noEmit`）
3. unit test（Vitest）
4. depcruise（dependency-cruiser）
5. build（Vite + CRXJS）

```json
{
  "scripts": {
    "verify": "pnpm lint && pnpm typecheck && pnpm test:unit && pnpm depcruise && pnpm build"
  }
}
```

コード変更後は必ず実行し、全パスすることを確認する。

Integration / E2E テストは Chrome の起動を伴い実行時間が長いため `verify` には含めず、CI と PR 前の手動実行で担保する。

**build を最後に含めるのは manifest 由来のエラーが型チェックでは検出できないため。** エントリの記述漏れ、`web_accessible_resources` の指定漏れ、Offscreen Document の HTML エントリ未登録は、ビルドまたは実行時にしか現れない。

## 型チェック (TypeCheck)

- `tsc --noEmit` で型エラーがないことを確認する
- **`any` の使用は原則禁止**（一時的な回避には `biome-ignore` コメントと理由を明記する）
- `@types/chrome` を導入し、`chrome.*` API を型付きで扱う
- **外部由来のデータは境界で必ず型を確定させる。** マニフェスト文字列のパース結果、`chrome.runtime.onMessage` のペイロード、Content Script から受け取るページ由来データは、キャストではなくバリデーションを通してから型を付ける
- CI で必ず実行。型エラーがある PR はマージ不可とする

## 依存方向チェック (Dependency Cruise)

`アーキテクチャ.md` で定義した依存方向を機械的に検証する。

```text
background ─┐
offscreen  ─┤
content    ─┼──→ processor ──→ media ──→ shared
popup      ─┘
```

最低限、以下のルールを定義する。

| ルール名 | 内容 |
|---|---|
| `no-core-to-context` | `shared/` `media/` `processor/` から `background/` `offscreen/` `content/` `popup/` への依存を禁止 |
| `no-cross-context` | `background/` `offscreen/` `content/` `popup/` 相互の import を禁止 |
| `shared-is-innermost` | `shared/` から他ディレクトリへの依存を禁止 |
| `media-depends-on-shared-only` | `media/` から `processor/` への依存を禁止 |
| `core-no-storage` | `media/` `processor/` から `shared/storage/` への依存を禁止（純粋性を守るため） |
| `no-circular` | 循環依存を禁止 |

```javascript
// .dependency-cruiser.cjs（抜粋）
module.exports = {
  forbidden: [
    {
      name: 'no-core-to-context',
      severity: 'error',
      comment: 'コアロジック層は実行コンテキストに依存してはならない',
      from: { path: '^src/(shared|media|processor)/' },
      to: { path: '^src/(background|offscreen|content|popup)/' },
    },
    {
      name: 'no-cross-context',
      severity: 'error',
      comment: '実行コンテキスト同士は別バンドル。メッセージ経由で通信する',
      from: { path: '^src/(background|offscreen|content|popup)/' },
      // $1 は from.path のキャプチャ。自分自身のディレクトリ内の import のみ許可する
      to: { path: '^src/(background|offscreen|content|popup)/', pathNot: '^src/$1/' },
    },
    {
      name: 'shared-is-innermost',
      severity: 'error',
      from: { path: '^src/shared/' },
      to: { path: '^src/(media|processor|background|offscreen|content|popup)/' },
    },
    {
      name: 'media-depends-on-shared-only',
      severity: 'error',
      from: { path: '^src/media/' },
      to: { path: '^src/processor/' },
    },
    { name: 'no-circular', severity: 'error', from: {}, to: { circular: true } },
  ],
}
```

違反があった場合、`biome-ignore` 的な抑制で回避せず、モジュールの切り出し・配置を見直す。

## コアロジック層の純粋性チェック

依存方向に加えて、**コアロジック層が `chrome.*` / DOM API を参照していないこと** を検証する。これが崩れると Unit テストが Node.js 上で動かなくなり、テスト戦略全体が破綻する。

Biome の `noRestrictedGlobals` で以下を `src/shared/` `src/media/` `src/processor/` に対して禁止する。

```text
chrome, document, window, Blob, localStorage
```

**禁止するグローバルには理由を添える。** Biome 2 の `deniedGlobals` は「グローバル名 → メッセージ」の対応を取るため、なぜ触ってはいけないか・代わりに何を使うかを違反箇所へ直接出せる。ルールに引っかかった人が規約を探しに行かずに済む形にしておくこと。

**`src/shared/storage/` のみ除外する。** Repository は `chrome.storage` を直接呼ぶ（`アーキテクチャ.md` の例外規定を参照）。例外がコアロジック層へ波及しないよう、`core-no-storage` ルールで `media/` `processor/` からの参照を禁止している。

副作用が必要な場合は Port（interface）として宣言し、実行コンテキスト層から Adapter を注入する（`アーキテクチャ.md` 参照）。

## カバレッジ

- 計測対象は **Unit テストで検証する層** に限定する。実行コンテキスト層（`background/` `offscreen/` `content/` `popup/`）と `shared/storage/`（`chrome.storage` を直接呼ぶ Repository）は Integration / E2E で担保するため計測から外す
- **除外設定は `vitest.config.ts` と `codecov.yml` の両方に書く。** 片方だけだとローカルの計測値と Codecov の判定がずれる
- HLS / DASH パーサー、URL 正規化、重複排除、ファイル名生成、DRM 判定、ブロックリスト判定は **カバレッジ 90% 以上** を目標とする
- カバレッジ低下を伴う PR は理由を PR 本文に記載する
