# Video Download Helper Repository レイヤー設計方針

本拡張はデータベースを持たない。永続化層は **`chrome.storage`** である。

`chrome.storage` への直接アクセスは `apps/extension/src/shared/storage/` に集約する。
Background / Offscreen / Content / Popup のいずれからも、必ず Repository 経由で読み書きする。

## ストレージ領域の使い分け

| 領域 | 用途 | 生存期間 | 上限 |
|---|---|---|---|
| `chrome.storage.session` | タブ単位の検出結果、ダウンロードタスクの状態 | ブラウザ起動中（Service Worker 再起動を跨いで復元可能） | 約 10MB |
| `chrome.storage.local` | ユーザー設定、ブロックリストのキャッシュ | 明示的に削除するまで永続 | 約 10MB |
| `chrome.storage.sync` | 端末間で共有したいユーザー設定（任意） | 永続 + 同期 | 約 100KB / 項目 8KB |

**検出結果とダウンロード状態は `session` を使う。** 要件定義 2.7 の「検出結果はタブのライフサイクル中のみ保持」を満たしつつ、Service Worker が停止しても状態を復元できる。`local` に置くと閲覧履歴がディスクへ残り、プライバシー方針に反する。

## 基本パターン

```typescript
// shared/storage/detected-media.repository.ts
import type { DetectedMedia } from '../types'

const KEY_PREFIX = 'detected-media:' as const

const tabKey = (tabId: number) => `${KEY_PREFIX}${tabId}` as const

export async function findDetectedMediaByTab(tabId: number): Promise<DetectedMedia[]> {
  const key = tabKey(tabId)
  try {
    const result = await chrome.storage.session.get(key)
    return (result[key] as DetectedMedia[] | undefined) ?? []
  } catch (error) {
    throw new Error(`検出結果の取得に失敗しました: ${String(error)}`)
  }
}

export async function saveDetectedMediaForTab(
  tabId: number,
  media: DetectedMedia[],
): Promise<void> {
  try {
    await chrome.storage.session.set({ [tabKey(tabId)]: media })
  } catch (error) {
    throw new Error(`検出結果の保存に失敗しました: ${String(error)}`)
  }
}

export async function clearDetectedMediaForTab(tabId: number): Promise<void> {
  await chrome.storage.session.remove(tabKey(tabId))
}
```

## 実装ルール

- **`chrome.storage` の呼び出しを Repository 内に閉じ込める。** background / offscreen / content / popup から直接呼ばない
- **キーは Repository 内で定数プレフィックス + 識別子から生成する。** 呼び出し元がキー文字列を組み立てない
- **Repository は「storage アクセス + 第一レイヤーのエラーハンドリング」のみを担当する。** 重複排除・URL 正規化・DRM 判定などのビジネスロジックは `media/` 側に残す
  - 例外として、タブ ID による絞り込みなど storage のキー設計に直結する操作は Repository 側で実装してよい
- **保存する値は必ず構造化クローン可能な plain object にする。** クラスインスタンス・`Map` / `Set` ・関数を保存しない。Service Worker 再起動後の復元がそのまま成立する形にする
- **認証情報を保存しない。** Cookie / Authorization ヘッダー、および URL クエリ中の認証トークンは保存前にマスキングする（要件定義 12 章）
- **タブのライフサイクルに合わせて破棄する。** `chrome.tabs.onRemoved` および メインフレームのページ遷移で該当タブのエントリを削除する。書き込みっぱなしにすると容量上限に達する
- **容量上限を前提に設計する。** セグメントのバイト列など大きなデータを storage へ置かない。ダウンロード中のバイト列は Offscreen Document のメモリ上にのみ保持する
- **書き込みは間引く。** ダウンロード進捗のような高頻度の更新をそのまま `set` しない。バッチ化またはデバウンスし、UI への通知はメッセージで行う

## Repository 一覧（想定）

| ファイル | 責務 | 領域 |
|---|---|---|
| `detected-media.repository.ts` | タブ単位の検出結果 | `session` |
| `download-task.repository.ts` | ダウンロードタスクの状態 | `session` |
| `settings.repository.ts` | 同時接続数・ファイル名テンプレート・サイズ警告閾値 | `local` |
| `blocklist.repository.ts` | ブロックリストのキャッシュ（判定ロジックは `media/blocklist.ts`） | `local` |

## テスト方針

Repository は `chrome.storage` に依存するため Unit テストの対象外とし、**Integration テストで検証する**（`テストガイドライン.md` 参照）。
Unit テストで Repository をモックしないよう、呼び出し元のビジネスロジックは Repository から独立した純粋関数として切り出しておくこと。
