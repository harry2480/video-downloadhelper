# Video Download Helper Popup UI 実装方針

## 1. 概要

Video Download Helper の唯一の UI である **Popup（`chrome.action.default_popup`）** の実装方針を定めます。

Web アプリのフロントエンドとは前提が大きく異なります。ルーティングも SSR も SEO も存在せず、代わりに以下の制約を前提に設計します。

- **揮発性**: ポップアップはフォーカスを失った瞬間に破棄される。ローカル state は保存されない
- **状態を所有しない**: 検出結果・ダウンロード進捗は Background Service Worker / Offscreen Document が所有する。Popup は購読して描画するだけ
- **固定寸法**: 幅 400〜480px / 高さ最大 600px。レスポンシブブレークポイントは不要で、代わりに内部スクロールを設計する
- **信頼できない入力**: 表示するタイトル・URL はすべてページ由来。サニタイズと折り返しを常に前提にする

## 2. 技術スタック

### コア技術
- **Framework**: React 19（ルーターなし・単一画面）
- **Language**: TypeScript
- **Styling**: Tailwind CSS（`darkMode: 'media'`）
- **State Management**: React state のみ。グローバル state ライブラリは導入しない
- **Data Fetching**: `chrome.runtime.connect` による long-lived port の購読
- **Persistence**: `chrome.storage`（Popup から直接触らず Repository 経由。`リポジトリ層設計規約.md` 参照）
- **UI Components**: 自前の最小コンポーネント群（依存を増やさない。shadcn/ui 等は導入しない）

### 開発ツール
- **Bundler**: Vite + `@crxjs/vite-plugin`
- **Linter/Formatter**: Biome（リポジトリ共通の `biome.json`）
- **Testing**: Vitest + React Testing Library（jsdom）
- **E2E Testing**: Playwright（`launchPersistentContext` で拡張機能をロード）

## 3. ディレクトリ構成

```text
apps/extension/src/popup/
├── index.html               # Vite エントリ HTML
├── main.tsx                 # エントリ兼 Composition Root（Port 実装の注入）
├── App.tsx                  # 画面全体の組み立て
├── components/
│   ├── MediaList.tsx        # 検出メディア一覧
│   ├── MediaItem.tsx        # 1 メディアの表示 + ダウンロードボタン
│   ├── MediaDetails.tsx     # URL / Content-Type / 検出方式の展開表示
│   ├── QualitySelector.tsx  # HLS / DASH の品質・音声選択
│   ├── DownloadProgress.tsx # 進捗バーとキャンセル
│   ├── StatusMessage.tsx    # 検出中 / 未検出 / エラー / DRM
│   └── ui/                  # Button, Badge, ProgressBar 等の最小プリミティブ
└── hooks/
    ├── use-media-list.ts    # 検出結果の購読
    ├── use-downloads.ts     # ダウンロードタスクの購読
    └── use-port.ts          # chrome.runtime.connect のライフサイクル管理
```

`popup/` からコアロジック層（`shared/` `media/` `processor/`）の import は可。他の実行コンテキスト（`background/` `offscreen/` `content/`）の import は **禁止**。

## 4. 機能要件

### Phase 1: MVP

#### 4.1 検出メディア一覧

- **要件**:
  - 現在アクティブなタブで検出されたメディアのみを表示する
  - 直接ダウンロード可能なメディアと、品質選択が必要なストリームを視覚的に区別する
  - DRM 判定されたメディアはダウンロード操作を提供せず、理由を表示する
- **表示項目**（要件定義 4.3）:
  - 動画タイトル / サイト名
  - 種別（MP4 / WebM / HLS / DASH / Audio）
  - 解像度・ビットレート・FPS
  - 映像コーデック・音声コーデック
  - 推定ファイルサイズ
  - ダウンロードボタン / 詳細表示ボタン
- **機能（初期スコープ）**:
  - ページネーション: なし（検出件数は現実的に数十件以内）
  - フィルタ・ソート: なし。並び順は「検出順」固定
  - 手動再スキャンボタンを提供する

#### 4.2 品質選択

- **要件**:
  - HLS / DASH では Variant を解像度降順で提示し、既定で最高品質を選択済みにする
  - DASH では音声トラックを映像と独立して選択できる
  - 推定サイズが上限（目安 2GB）を超える選択には警告を表示する

#### 4.3 ダウンロード状態表示

- **要件**:
  - 進捗率をバーと数値で表示（映像・音声を通算した 0〜100）
  - 「結合しています…」等の後処理フェーズを区別して表示する
  - キャンセル・失敗時の再試行を提供する
  - **ポップアップを閉じて再度開いても進捗が復元される**（状態は Background が所有するため）

### Phase 2: 機能拡張

- 複数ダウンロードの同時表示とキュー
- 設定画面（同時接続数、ファイル名テンプレート、サイズ警告閾値）
- 字幕・音声トラックの選択 UI

## 5. 非機能要件

### パフォーマンス

- **ポップアップ初期描画: 100ms 以内。** 開いた瞬間に「何もない画面」を見せない
- 初回描画は購読前の既知状態（Background が保持する最新スナップショット）を即座に反映する
- ffmpeg.wasm 等の重量モジュールを Popup バンドルへ含めない（Offscreen Document 専用）
- 進捗更新は 200ms 程度に間引いて再描画コストを抑える

### アクセシビリティ

- WCAG 2.1 Level AA 準拠（コントラスト比 4.5:1 以上）
- キーボードのみで一覧の走査・品質選択・ダウンロード実行が完結すること
- すべてのアイコンボタンに `aria-label` を付与する
- 品質選択はネイティブの `radiogroup` セマンティクスを用いる
- ダウンロード状態の変化を `aria-live="polite"` で通知する

### セキュリティ

- **ページ由来の文字列を `dangerouslySetInnerHTML` へ渡さない。** 例外なし
- URL は表示前に長さを制限し、認証トークンらしきクエリはマスキングして表示する
- 外部ホストへのリクエストを行わない（画像・フォント・スクリプトをすべて同梱する）。Manifest V3 の CSP に準拠し、リモートコードを実行しない

## 6. 実装ガイドライン

### コーディング規約

1. **コンポーネント設計**
   - 単一責任。表示と副作用（メッセージ送信）を混在させない
   - Props interface を明示的に定義する。`React.FC` は使わない
   - 副作用は hooks に閉じ、コンポーネントは受け取った props の描画に徹する
2. **型定義**
   - `any` 禁止。Background から受け取るメッセージは `shared/messages.ts` の型で受ける
   - 表示用の型を Popup 側で再定義しない。`shared/types.ts` を単一の情報源とする
3. **スタイリング**
   - Tailwind のユーティリティファースト
   - 直値カラー禁止（`スタイルガイド.md` 参照）
   - `vh` / `dvh` 禁止。固定 px + 内部スクロール（`スタイルガイド.md` 参照）

### アーキテクチャ原則

1. **状態を所有しない**: Popup の state は「表示のための派生」に限る。真実の情報源は常に Background
2. **明確な責任分離**: components（描画）/ hooks（購読・送信）/ shared（型・ロジック）
3. **依存関係の管理**: 他の実行コンテキストを import しない。循環参照を作らない
4. **テスタビリティ**: 表示判定ロジック（サイズ整形、解像度ラベル、状態文言）は純粋関数として `shared/` または `popup/` 内の util へ切り出し、コンポーネントに埋め込まない

## 7. 実装順序

1. **基盤構築**
   - Vite + React + Tailwind のセットアップ、`index.html` と `main.tsx`
   - `ui/` の最小プリミティブ（Button / Badge / ProgressBar）
2. **購読層の実装**
   - `use-port.ts` → `use-media-list.ts` → `use-downloads.ts`
   - Background 未実装の段階では Fake port で先行実装できるようにする
3. **表示コンポーネント実装**
   - StatusMessage → MediaList → MediaItem → MediaDetails → QualitySelector → DownloadProgress
4. **App への統合**
   - 状態遷移（検出中 / 未検出 / 一覧 / ダウンロード中 / エラー / DRM）の網羅

## 8. テスト戦略

### ユニットテスト
- 表示用の整形関数（バイト数の人間可読化、解像度ラベル、ビットレート表記）
- 状態から表示すべきメッセージを決める判定関数
- カスタムフックのメッセージハンドリング（Fake port を注入）

### 統合テスト
- React Testing Library + Fake port による画面全体のレンダリング
- 各状態（検出中 / 未検出 / DRM / エラー / 進捗中）のスナップショット的検証
- キーボード操作のみでダウンロードまで到達できること

### E2E テスト（対象スコープ）
- テストページを開く → 検出 → バッジ → ポップアップ → 品質選択 → ダウンロード完了までのクリティカルパス
- ポップアップを閉じて再度開いた際に進捗が復元されること

## 9. 配布戦略

- **配布先**: Chrome Web Store（`インフラストラクチャ規約.md` 参照）
- **ビルド成果物**: `apps/extension/dist/` を zip 化してアップロード
- **環境変数管理**: なし。拡張機能はバックエンドを持たず、シークレットを同梱しない
- **CI/CD**: GitHub Actions で lint / typecheck / test / build を実行し、zip をアーティファクトとして保存する
- **プレビュー環境**: 該当なし。PR ごとにビルド済み zip を添付し、レビュアーが `chrome://extensions` へ手動ロードして確認する
