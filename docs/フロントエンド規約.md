# Video Download Helper フロントエンド規約

React + Tailwind CSS による Chrome 拡張 Popup UI の規約。詳細な実装方針は `フロントエンドアーキテクチャ.md` を参照。

---

## ディレクトリ構成

`apps/extension/src/` 配下:

| ディレクトリ | 責務 |
|---|---|
| `popup/` | Popup UI のエントリ（`index.html` / `main.tsx`）。UI に関わるコードはすべてここに閉じる |
| `popup/components/` | React コンポーネント。描画に専念し、`chrome.*` を直接呼ばない |
| `popup/components/ui/` | Button / Badge / ProgressBar 等の最小プリミティブ。プロダクト固有の意味を持たせない |
| `popup/hooks/` | Background との購読・送信を担うカスタム hooks。副作用はここに閉じる |
| `shared/` | 型・メッセージ定義・純粋 util。Popup と他コンテキストの共通言語 |
| `background/` `offscreen/` `content/` | 別コンテキスト。**Popup からの import 禁止**（`アーキテクチャ.md` 参照） |

---

## コンポーネント / hooks の使い分け

- **デフォルトはコンポーネント。** `chrome.*` を呼ぶ必要が生じたら hooks へ切り出す
- コンポーネントに書いてよいのは「props を受け取って描画する」ことだけ。`chrome.runtime` / `chrome.storage` / `chrome.tabs` の直接呼び出しは **禁止**
- hooks が必要なケース: Background との port 接続、メッセージ送信、`chrome.storage` の読み書き、タイマー・購読の解除が必要な処理
- **初期データは必ず購読（`use-media-list` / `use-downloads`）で取得する。** コンポーネント内で個別に `sendMessage` しない

---

## データフローと状態管理

- **状態管理**: グローバル state ライブラリを導入しない。React の `useState` / `useReducer` のみを使い、真実の情報源は常に Background Service Worker 側に置く
- **データフェッチ**: `chrome.runtime.connect` による long-lived port で購読し、受信したメッセージを state へ反映して props として下ろす。コンポーネント側での追加取得は行わない
- **ミューテーション**: ダウンロード開始・キャンセル・再スキャンは Background へメッセージを送るだけで、結果を楽観的更新しない。Background から返る `download-updated` を待って描画する

```text
Background（状態の所有者）
   │  port.postMessage
   ▼
hooks（購読・整形）
   │  props
   ▼
components（描画のみ）
   │  onClick → hooks の送信関数
   ▼
Background（状態を更新）
```

## 表示の安全性

Popup が表示する文字列（動画タイトル・ページタイトル・URL）は **すべてページ由来の信頼できない入力** である。

- `dangerouslySetInnerHTML` の使用禁止。例外なし
- URL は表示前に短縮し、クエリ中の認証トークンらしき値はマスキングする
- 長大な文字列によるレイアウト破壊を防ぐため、折り返し / 省略を必ず指定する（`スタイルガイド.md` 参照）
- 外部ホストの画像・フォント・スクリプトを読み込まない。すべて拡張機能内に同梱する
