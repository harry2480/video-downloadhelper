## 対象

$ARGUMENTS

## タスク

指定された機能に対する E2E テストを Playwright で作成してください。

### 1. 対象の特定

- 引数が指定されている場合: その機能を対象とする
- 引数がない場合: 以下の順で対象を特定する
  1. unstaged の変更ファイル (`git diff --name-only`)
  2. main ブランチからの差分 (`git diff --name-only main...HEAD`)

対象ファイルから `apps/extension/src/` 配下の変更を抽出し、E2E で確認すべきユーザーフローを特定する。

### 2. 対象機能の調査

1. **フローの把握**: 対象機能について以下を確認する
   - どのコンテキストが関与するか（content → background → offscreen → popup）
   - ユーザーの操作起点（ページを開く / ポップアップを開く / ボタンを押す）
   - 観測可能な結果（バッジの数字、ポップアップの表示、ダウンロードされたファイル）

2. **フィクスチャの確認**: `apps/extension/test/fixtures/pages/` に対象を再現できるテストページがあるか確認する。なければ追加する（`docs/テストガイドライン.md` のフィクスチャ一覧を参照）

3. **既存テストの参考**: `apps/extension/test/e2e/` 配下

### 3. テストケースの設計

E2E は**検出からダウンロード完了までのクリティカルパス**に集中する。マニフェスト解析の細部やエッジケースは Unit テストで担保するため、E2E では扱わない。

**検出テスト**
- テストページを開くとメディアが検出されるか
- バッジに正しい件数が表示されるか
- ポップアップに正しい情報（種別・解像度・推定サイズ）が表示されるか

**ダウンロードテスト**
- 品質を選択してダウンロードが完了するか
- 生成されたファイルが妥当か（サイズ > 0、TS なら先頭が同期バイト `0x47`）

**状態テスト**
- タブごとに検出結果が分離されているか（2タブで相互汚染しない）
- ポップアップを閉じて再度開いても進捗が復元されるか
- Service Worker 停止後も処理が継続するか

### 4. テスト実装

以下のルールに従ってテストを実装する：

1. **拡張機能のロード**: `launchPersistentContext` + `--load-extension` + `--headless=new` を使う。従来の headless では拡張機能が動作しない

2. **拡張機能 ID**: 起動ごとに変わるため、Service Worker の URL から動的に取得してポップアップ URL を組み立てる
   ```typescript
   const worker = await context.waitForEvent('serviceworker')
   const extensionId = new URL(worker.url()).host
   ```

3. **ロケーター**: 堅牢なロケーターを使用する
   - `getByRole`, `getByLabel`, `getByText` を優先
   - `.first()` は避け、特定の要素を明示的に選択する

4. **外部ネットワークへ出ない**: テスト対象のメディアはローカルの静的サーバーから配信する

5. **検証は実ファイルで行う**: ダウンロード完了は `chrome.downloads` の状態ではなく、生成されたファイルのサイズと先頭バイトで確認する

6. **テストデータ**: ダウンロードファイル名は一意性を確保する（例: `test-${Date.now()}.ts`）

7. **ファイル配置**: `apps/extension/test/e2e/{機能名}.spec.ts`

### 5. テスト実行

E2E は **ビルド済みの `dist/` を読み込む**ため、先にビルドが必要。

```bash
pnpm build
pnpm test:e2e --grep "{テスト名}"
```
